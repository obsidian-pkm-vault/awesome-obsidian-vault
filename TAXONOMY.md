# Proposed taxonomy for Obsidian vaults and websites

This document defines a simple, scalable taxonomy for the list of vaults and websites.
The goal is to keep the classification easy to scan while leaving room for future additions.

## 1. Core principles

- Each entry should have one primary category.
- Optional secondary tags can describe format, audience, or use case.
- Categories should stay broad enough to absorb future entries without becoming too fragmented.
- Category names should be human-readable and consistent with the table.

## 2. Proposed taxonomy

### Primary categories

- Computing & Software
- Digital Gardens & Publishing
- Documentation & Knowledge
- Education & Learning
- Knowledge Bases & Wiki Vaults
- Food & Lifestyle
- Personal Websites & Indie Web
- Programming & Software
- Science & Research
- Sample Vaults & Templates
- Web Directories & Media

### Secondary tags

- Format: vault, website, template, dataset, hybrid
- Use case: reference, learning, personal archive, community resource
- Highlight: featured / standout

## 4. Recommended naming rules

- Prefer broad, durable names over overly specific ones.
- Use “&” rather than “and” when space is limited.
- Keep names consistent in title case.
- If a category contains only one or two entries, consider merging it into a broader parent category.
